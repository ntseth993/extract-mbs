Build a complete **Smart Download Accelerator** as a browser extension with a backend server.

## 1. Main Goal

Create a browser extension that makes large file downloads as fast and reliable as possible by intelligently using the user's available network bandwidth.

The system must NOT claim to extract MB directly from a SIM card or create free mobile data. The user's mobile-data bundle remains controlled by the network operator.

Instead, the system should optimize legitimate downloads using:

* Multiple simultaneous connections
* HTTP range requests
* Parallel downloading
* Intelligent chunk sizing
* Connection management
* Download caching
* Automatic retry
* Download resumption
* Bandwidth monitoring
* Network-aware optimization

The user should be able to enter or click a file download and have the extension accelerate the download automatically.

# 3. Download Acceleration Algorithm

When a user requests a file:

1. Detect the download URL.
2. Send a HEAD request where supported.
3. Determine:

   * File size
   * Content type
   * Server response
   * Whether HTTP Range Requests are supported
   * Content length
4. If range requests are supported, divide the file into chunks.
5. Start several simultaneous HTTP requests.

Example:

A 1 GB file could be divided into:

```text
Chunk 1 → 0–100 MB
Chunk 2 → 100–200 MB
Chunk 3 → 200–300 MB
Chunk 4 → 300–400 MB
...
```

Download multiple chunks simultaneously.

6. Monitor each connection.
7. Dynamically increase or decrease the number of connections depending on:

   * Available bandwidth
   * Latency
   * Server response
   * CPU usage
   * Network stability
8. Retry failed chunks automatically.
9. Resume interrupted downloads.
10. Verify every chunk.
11. Reassemble the chunks in the correct order.
12. Verify the final file.
13. Save the completed file to the user's chosen download location.

# 4. Important Optimization

Do NOT simply create 100 connections.

Implement an adaptive algorithm.

Example:

```text
Start with 4 connections

Measure performance

If bandwidth improves:
    increase to 6

If bandwidth improves:
    increase to 8

If bandwidth decreases:
    reduce to 6

If server rejects requests:
    reduce connections

Maximum:
    configurable by the user
```

Default maximum should be reasonable, such as 8 connections.

Allow the user to configure:

```text
Connections:
[4]

Maximum connections:
[8]

Chunk size:
[10 MB]

Automatic optimization:
[ON]
```


# 11. Fallback System

Not every server supports parallel range downloads.

If Range Requests are unavailable:

```text
Range supported?
       │
   ┌───┴───┐
  YES      NO
   │        │
Parallel   Normal
download   download
```

The extension should automatically fall back to a normal download.

# 12. Security

Implement:

* HTTPS
* Input validation
* URL validation
* Authentication if accounts are implemented
* Rate limiting
* Secure API keys
* No arbitrary server-side URL fetching without protection
* Protection against SSRF
* File-type validation
* File integrity checks
* SHA-256 verification where appropriate

Do not download or execute dangerous files automatically.

```text
POST /api/download/cancel
GET  /api/download/:id
GET  /api/download/:id/progress
```

```json
  "downloadId": "abc123",
  "fileName": "example.zip",
  "fileSize": 1073741824,
  "supportsRange": true,
  "recommendedConnections": 8

```

# 18. Important Product Principle

The application must clearly explain:

> "Smart Download Accelerator optimizes how your internet connection downloads files. It cannot create free mobile data, extract MB from a SIM card, or bypass your mobile network operator's data limits."

The goal is to make the **existing internet connection more efficiently utilized**, not to bypass telecom billing.
